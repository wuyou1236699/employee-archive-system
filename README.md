# 员工档案管理系统

这是从零逐步开发员工档案系统的中文工程展示，保留 React + TypeScript 前端、CloudBase 云函数后端、权限与审计接口，以及有效回归测试。开发过程中使用 AI 辅助编码、定向审查和验证。

展示源码以 2026 年 10 月完成上线的业务实现为基础，演示资料与组织评分文案重新编写。这里不是正式系统的部署包，不含正式环境配置，也不代表新环境已经部署或通过云端验收。

## 可以看到什么

员工档案列表与详情、合同和车辆编辑、图片附件登记、课程和事件记录、账号权限、审计、月度与季度评价的界面和服务分层。未配置云端时，这些入口使用内存模拟；涉及真实云端身份、事务、存储和跨实例并发的行为须在自己的隔离环境验收。

公开演示的季度维度、评分说明和全部样例记录都是虚构内容，不是任何单位的考评制度。演示手机号仅供格式校验，不应拨打；号牌不是合法车牌。未携带附件文件、真实账号、员工记录、组织资料或数据库快照。

## 三项工程修复

- **附件安全**：登记与成功审计事务化，保留幂等、同键元数据核对、存储路径及查看权限校验，避免失败清理误删已引用图片。
- **合同保存**：嵌套合同与 null 经过白名单归一化后持久化；修改保留编号，显式清空优先于旧字段；支持已有扁平合同的读取与旧客户端提交。
- **车辆保存**：嵌套车辆与 null 正确保存；新增由服务端生成编号，修改保留编号和扩展元数据；省略车辆字段不改原值，兼容旧客户端扁平请求。不猜测未知旧文档结构或独立车辆集合关联。

原系统的隔离验证记录为附件 18/18、合同 7/7、车辆 9/9。这是业务实现的来源验证，不是公开展示版本的云端验收。上线只核对了读取及相关入口，没有在真实员工记录上补做保存或附件上传测试。真实云端日志、隔离函数和测试资料不随源码公开。

## 本地体验

建议 Node.js 24；部分图片测试使用全局 File。后端源码的目标运行时为 Node.js 18.15。

```sh
npm ci --ignore-scripts --no-audit --no-fund
npm run dev
# 打开页面后选择体验入口，数据只在内存中保存，刷新后重置。
npm test
npm run build
npm run preview
```

开发和构建预览默认都使用离线演示。只有 VITE_ENABLE_CLOUDBASE 精确为 true，并填写自己的环境 ID 与浏览器 publishable key，才可能初始化云端 SDK；仅存在环境配置不会自动开启连接。不要将服务端密钥写入 VITE 变量。本地测试使用虚构输入和 Mock/内存适配器，不调用真实数据库。

```sh
cd backend/employeeArchiveApi
npm ci --ignore-scripts --no-audit --no-fund
npm run check
npm test
```

后端 @cloudbase/node-sdk 固定为 3.18.3，npm-shrinkwrap.json 固定传递依赖。依赖锁文件没有为展示升级。虚构 storage authority 不能直接用于真实部署；请在自己的环境核实身份、权限、索引、存储路径与事务行为。

## 本次验证与边界

前端测试、类型检查、构建及后端检查的最终结果见 [展示安全与验证记录](docs/ARCHIVE_SCOPE.md)。完整后端测试有一项已知注册诊断计数失败（实际 2、期望 1）；既有 lint 问题仅记录，未借展示准备修复无关代码。构建可能提示包体积较大。

本地附件、合同、车辆测试覆盖业务入口、提交、保存和读回，但不能替代真实 CloudBase 持久化、事务隔离、权限及跨实例并发验收。未提供可直接操作任何正式环境的部署脚本。
